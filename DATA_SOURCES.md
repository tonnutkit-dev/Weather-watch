## Licensing decision
Local, personal noncommercial prototype only, no ads/subscriptions. Portfolio promotional use can be classified commercial by Open-Meteo terms; public portfolio publication requires resolving that use classification before deployment. RainViewer personal API is not blanket commercial authorization. No plan purchased. License audit is documentary, not a legal clearance. Font Noto Sans Thai SIL OFL bundled by npm, Lucide ISC, MapLibre BSD-3-Clause; preserve installed licenses. No OSM public raster tile server.

## Conflicting documentation
RainViewer general FAQ still mentions nowcast, while dedicated transition and Weather Maps documentation describe past-only. Implement `radar.past` exclusively, discard any future time, never consume `nowcast`. Legend uses documented scheme 2 (Universal Blue), qualitative light-to-heavy, not fabricated mm/h thresholds. Coverage mask is infrequently updated and cannot prove exact present coverage. Display blanket blank-image caveat and China limitation.

## Provider envelopes and accuracy
Every normalized dataset has source, type, fetchedAt, requested coordinates, units/status/attribution. observedAt/issuedAt/validFrom/validTo nullable; provider timestamps preserved. AQ and current weather are model estimates, not station measurements. Forecast confidence decreases with horizon. No flood-free classification; no unavailable alerts interpreted as zero alerts.

## Executed verification summary
Weather and AQ HTTP200 for Bangkok, Chiang Mai, Phuket and all three permitted Chinese cities (12 responses); every weather response supplied 16 daily entries. RainViewer metadata contained real historical frames (13 in audit, 12 in later browser refresh), with successful radar PNG and coverage PNG. OpenFreeMap light/dark style JSON HTTP200; vector rendering NOT TESTED in cloud Chrome because WebGL was disabled. Thai geocoding returned Chiang Mai and Bang Lamung. Flood/GloFAS HTTP200 daily discharge: feasibility only, deliberately absent from product views. GISTDA/ThaiWater portal and TMD documentation HTTP200 prove only website access, NOT flood/gauge/alert dataset integration. Raw response/time/status evidence is in evidence/provider-results.json. Subsequent browser requests were live and independent of captured fixtures.
